# Villager Orders — Forge 1.20.1

مود لماينكرافت Java Edition يتيح إعطاء أوامر مؤقتة لأي قروي.

## الأوامر داخل اللعبة

| الزر | الأيقونة | ماذا يفعل؟ |
|---|---|---|
| **Follow Me** | Lead | يتبع اللاعب الذي أصدر الأمر ويحاول البقاء قريبًا منه. |
| **Stay Here** | Redstone Block | يبقى في مكانه ويتوقف عن التجول. |
| **Hide From Monsters** | Oak Door | عند اقتراب الوحوش المعادية يبحث عن مكان مغطى وآمن، وإذا لم يجد مكانًا مناسبًا يبتعد عن الوحش. |
| **Resume Normal Behavior** | — | يلغي الأمر الحالي ويزيل بيانات الأمر، فيعود القروي إلى ذكائه وسلوكه الافتراضيين. |

تُعرض نافذة فيها اسم القروي وصحته الحالية والقصوى، مع أيقونة وشرح بجانب كل أمر.

## التحكم

- **Right-click** على القروي لفتح نافذة الأوامر.
- **Shift + Right-click** لفتح واجهة التجارة العادية بدل نافذة الأوامر.
- اضغط **Resume Normal Behavior** في أي وقت لإلغاء الأمر.

## المتطلبات

- Minecraft Java Edition **1.20.1**
- Minecraft Forge **47.2.0** أو أحدث من سلسلة Forge الخاصة بـ 1.20.1
- Java **17**

## بناء ملف JAR على Windows 11

1. ثبّت Java 17 (JDK) وMinecraft Forge 1.20.1.
2. افتح مجلد المشروع في IntelliJ IDEA أو افتحه كمشروع Gradle في بيئة تطوير تدعم Gradle.
3. شغّل مهمة Gradle المسماة `build`.
4. بعد نجاح البناء ستجد الملف داخل `build/libs/` باسم قريب من `villagerorders-1.0.0.jar`.
5. انسخ ملف JAR إلى مجلد `.minecraft/mods` ثم شغّل ملف Forge 1.20.1 من المشغّل.

يمكن أيضًا تنفيذ الأمر `gradle build` من موجّه الأوامر داخل مجلد المشروع إذا كان Gradle مثبتًا ومضافًا إلى PATH.

## ملاحظات تقنية

- الأوامر تحفظ على القروي، ويُحفظ أمر Follow مع UUID اللاعب الذي اختاره.
- لا يتم استبدال Villager Brain ولا حذف أهداف الذكاء الاصطناعي الافتراضية. المود يضيف هدف حركة مؤقتًا ويتحكم في هدف المشي فقط أثناء وجود الأمر.
- أمر Hide يعمل عند وجود وحش معادٍ قريب؛ في غياب الخطر يعود القروي إلى سلوكه المعتاد إلى أن يظهر تهديد.
- يجب اختبار سلوك الاختباء في عالمك؛ فقد لا توجد دائمًا مساحة مغطاة صالحة للمسار، وعندها يحاول القروي الابتعاد عن الوحش بدلًا من ذلك.

## رفع المشروع إلى GitHub وتنزيل ملف المود تلقائيًا

أضف المشروع إلى مستودع GitHub مع الحفاظ على بنية المجلدات، بما فيها `.github/workflows/build-release.yml`.

1. أنشئ مستودعًا جديدًا في GitHub.
2. فك ضغط أرشيف المشروع، ثم ارفع **محتويات مجلد `VillagerOrders`** إلى جذر المستودع، وليس ملف ZIP وحده.
3. تأكد من وجود الملف `.github/workflows/build-release.yml` داخل المستودع.
4. من تبويب **Settings → Actions → General**، تأكد أن صلاحيات Workflow تسمح بالكتابة إلى Contents (Read and write)، إذا كانت إعدادات المستودع تمنع ذلك.
5. افتح **Releases → Draft a new release**، وأنشئ الوسم `v1.0.0` واختر الفرع `main` ثم انشر الإصدار.
6. سيبدأ GitHub Actions ببناء المود. راقب تبويب **Actions** حتى تنتهي المهمة بنجاح.
7. بعد النجاح، افتح الإصدار من **Releases** ونزّل ملف `villagerorders-1.0.0.jar` من قسم Assets.

يمكن تشغيل البناء يدويًا أيضًا من **Actions → Build Villager Orders → Run workflow**؛ وفي هذه الحالة يظهر ملف JAR ضمن Artifacts في صفحة تشغيل المهمة.

ملاحظة: ملف ZIP المصدر ليس مودًا قابلًا للتثبيت. الملف الذي يوضع داخل مجلد `mods` هو ملف `.jar` الناتج من عملية البناء. لم يتم اختبار البناء داخل اللعبة بعد.
